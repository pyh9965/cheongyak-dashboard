## 개요

| 항목 | 내용 |
|------|------|
| **기능명** | 세부 지역(시/군/구) 검색 필터 |
| **작성일** | 2025-02-03 |
| **버전** | v1.0 |
| **우선순위** | Medium |
| **예상 복잡도** | Medium |

## 1. 배경 및 목적

### 현재 상황
- 사용자는 시/도(광역시/도) 단위로만 지역 필터링 가능
- 예: "경기도" 선택 시 경기도 전체 청약 정보 표시
- 특정 시/군/구(예: 성남시, 목포시)만 보고 싶어도 전체 시/도 데이터를 확인해야 함

### 사용자 니즈
- "전라남도 → 목포시"와 같이 세부 지역까지 필터링하고 싶음
- 관심 지역의 청약 정보만 빠르게 확인하고 싶음

### 목표
- 계층적 지역 선택 UI 제공 (시/도 → 시/군/구)
- 사용자 경험 개선 및 정보 탐색 효율성 향상

## 3. 기술 분석

### 3.1 현재 데이터 구조

```typescript
interface AptInfo {
  SUBSCRPT_AREA_CODE: string;      // 시/도 코드 (예: "46")
  SUBSCRPT_AREA_CODE_NM: string;   // 시/도명 (예: "전남")
  HSSPLY_ADRES: string;            // 전체 주소 (예: "전라남도 목포시 ...")
  // ... 기타 필드
}
```

### 3.2 활용 가능한 기존 코드

| 파일 | 기능 | 활용 방안 |
|------|------|-----------|
| `src/lib/address-parser.ts` | 주소 파싱 | `parseAddress()` 함수로 시/군/구 추출 |
| `src/components/SearchForm.tsx` | 검색 폼 UI | 시/군/구 드롭다운 추가 |
| `src/hooks/useAptData.ts` | 필터링 로직 | 시/군/구 필터 조건 추가 |

### 3.3 address-parser.ts 파싱 결과 예시

```typescript
parseAddress("전라남도 목포시 옥암동 123")
// 결과:
{
  sido: "전남",
  sigungu: "목포시",
  fullKey: "전남 목포시"
}
```

## 4. UI/UX 설계

### 4.1 와이어프레임

```
┌─────────────────────────────────────────────────────────────┐
│  지역 선택                                                   │
│  ┌──────────────────┐  ┌──────────────────┐                │
│  │ 전라남도       ▼ │  │ 목포시         ▼ │                │
│  └──────────────────┘  └──────────────────┘                │
│       [시/도]              [시/군/구]                       │
│                        (시/도 선택 시 활성화)               │
└─────────────────────────────────────────────────────────────┘
```

### 4.2 상태 흐름

```
1. 초기 상태
   - 시/도: "전체"
   - 시/군/구: 비활성화 (disabled)

2. 시/도 선택 (예: 전라남도)
   - 시/군/구: 활성화
   - 시/군/구 목록: ["전체", "목포시", "여수시", "순천시", ...]

3. 시/군/구 선택 (예: 목포시)
   - 필터 적용
   - 결과: 목포시 청약만 표시

4. 시/도 변경 (예: 경기도로 변경)
   - 시/군/구: 자동 초기화 → "전체"
   - 시/군/구 목록: ["전체", "수원시", "성남시", ...]
```

### 4.3 반응형 레이아웃

| 화면 | 레이아웃 |
|------|----------|
| Desktop | 시/도, 시/군/구 가로 배치 |
| Mobile | 시/도, 시/군/구 세로 배치 (풀 너비) |

## 6. 기술적 고려사항

### 6.1 주소 파싱 정확도

**문제점:**
- `HSSPLY_ADRES`의 주소 형식이 일관되지 않을 수 있음
- 예: "경기도 성남시 분당구" vs "경기 성남 분당"

**해결 방안:**
- `address-parser.ts`의 정규화 로직 활용
- 파싱 실패 시 해당 항목은 "전체" 필터에만 포함

### 6.2 시/군/구 목록 동적 생성

**옵션 A: 사전 정의 (Static)**
```typescript
const SIGUNGU_MAP = {
  "46": ["목포시", "여수시", "순천시", ...], // 전라남도
  "41": ["수원시", "성남시", "안양시", ...], // 경기도
};
```

**옵션 B: 데이터 기반 동적 생성 (Dynamic) - 권장**
```typescript
// 실제 데이터에서 시/군/구 추출
const getSigunguList = (data: AptInfo[], sidoCode: string) => {
  return [...new Set(
    data
      .filter(item => item.SUBSCRPT_AREA_CODE === sidoCode)
      .map(item => parseAddress(item.HSSPLY_ADRES).sigungu)
      .filter(Boolean)
  )].sort();
};
```

**권장: 옵션 B (동적 생성)**
- 데이터가 없는 지역은 자동으로 제외
- 유지보수 불필요

### 6.3 성능 최적화

- 시/군/구 목록은 시/도 변경 시에만 재계산
- `useMemo`로 메모이제이션 적용
- 전체 데이터 로드 후 클라이언트 사이드 필터링
