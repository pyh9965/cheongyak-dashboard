## 1. 프로젝트 개요

### 1.1 서비스 설명

청약홈 공공데이터 API를 활용한 **APT 분양정보 및 경쟁률 조회 대시보드**입니다.

### 1.2 주요 기능

| 기능 | 설명 |
|------|------|
| **분양정보 조회** | 지역/기간/주택유형별 필터링 |
| **경쟁률 분석** | 특별공급/1순위/2순위/전체 경쟁률 |
| **지도 시각화** | Leaflet 기반 지역별 분양 현황 |
| **통계 대시보드** | Chart.js 기반 추이 분석 |
| **엑셀 다운로드** | 조회 결과 Excel 내보내기 |

### 1.3 코드 규모

```
총 코드: ~4,000줄 (TypeScript/React)
주요 페이지: 1개 (apt/page.tsx - 2,233줄)
컴포넌트: 5개
API 라우트: 2개
유틸리티: 6개
```

## 5. 웹 배포 옵션 비교

### 5.1 플랫폼별 비교표

| 플랫폼 | 난이도 | 무료 티어 | 장점 | 단점 |
|--------|--------|-----------|------|------|
| **Vercel** | ⭐ 매우 쉬움 | ✅ 충분함 | Next.js 최적화, 자동 CI/CD | 대용량 정적 파일 제한 |
| **Netlify** | ⭐⭐ 쉬움 | ✅ 있음 | 쉬운 설정, 좋은 CDN | Next.js 일부 기능 제한 |

| **AWS Amplify** | ⭐⭐⭐ 보통 | ✅ 있음 | 확장성, AWS 통합 | 설정 복잡 |
| **Cloudflare Pages** | ⭐⭐ 쉬움 | ✅ 관대함 | 빠른 CDN, 무제한 대역폭 | Edge 함수 제한 |

### 5.2 이 프로젝트에 적합한 순위

1. **🥇 Vercel** - Next.js 공식 플랫폼, 가장 쉬움
2. **🥈 Cloudflare Pages** - 무료 대역폭 무제한
3. **🥉 Railway** - 유연한 백엔드 지원

## 6. 추천 배포 방법: Vercel

### 6.1 왜 Vercel인가?

- ✅ **Next.js 제작사**가 운영 → 최적의 호환성
- ✅ **GitHub 연동** → Push만 하면 자동 배포
- ✅ **무료 티어** → 개인 프로젝트에 충분
- ✅ **글로벌 CDN** → 빠른 로딩
- ✅ **환경변수 관리** → 대시보드에서 쉽게 설정
- ✅ **자동 HTTPS** → SSL 인증서 자동 발급

### 6.2 Vercel 무료 티어 제한

| 항목 | 제한 |
|------|------|
| 대역폭 | 100GB/월 |
| Serverless 함수 실행 | 100GB-Hours/월 |
| 빌드 시간 | 6,000분/월 |
| 동시 빌드 | 1개 |
| 정적 파일 | 단일 파일 50MB 이하 |

> ⚠️ `cheongyak-details-cache.json`이 11MB이므로 문제없음

### 6.3 배포 단계

#### Step 1: GitHub 저장소 준비

```bash
# 현재 프로젝트를 GitHub에 푸시
git init
git add .
git commit -m "Initial commit"
git branch -M main
git remote add origin https://github.com/YOUR_USERNAME/cheongyak-dashboard.git
git push -u origin main
```

#### Step 2: Vercel 계정 생성 및 연결

1. https://vercel.com 접속
2. "Sign up" → GitHub 계정으로 로그인
3. "Add New Project" 클릭
4. GitHub 저장소 선택

#### Step 3: 프로젝트 설정

```
Framework Preset: Next.js (자동 감지됨)
Root Directory: ./
Build Command: npm run build (기본값)
Output Directory: .next (기본값)
Install Command: npm install (기본값)
```

#### Step 4: 환경변수 설정

Vercel 대시보드 → Settings → Environment Variables:

| Key | Value | Environment |
|-----|-------|-------------|
| `REB_API_KEY` | 공공데이터포털 API 키 | Production, Preview, Development |
| `NEXT_PUBLIC_KAKAO_API_KEY` | Kakao API 키 | Production, Preview, Development |

#### Step 5: 배포

"Deploy" 버튼 클릭 → 자동 빌드 및 배포

#### Step 6: 도메인 설정 (선택)

- 기본: `your-project.vercel.app`
- 커스텀 도메인: Settings → Domains → Add

### 6.4 배포 후 자동화

GitHub에 Push할 때마다:
1. Vercel이 자동으로 감지
2. 새 빌드 실행
3. Preview URL 생성 (PR인 경우)
4. Production 자동 배포 (main 브랜치)

## 7. 대안 배포 방법

### 7.1 Cloudflare Pages (무료 대역폭 무제한)

```bash
# 1. Cloudflare Pages에서 프로젝트 생성
# 2. GitHub 연결
# 3. 빌드 설정:
#    - Build command: npm run build
#    - Build output: .next
#    - Root directory: /

# 4. 환경변수 설정
# 5. 배포
```

**장점:** 무제한 대역폭, 빠른 글로벌 CDN
**단점:** Next.js 일부 기능 제한 (ISR 등)

### 7.2 Railway (백엔드 통합 필요시)

```bash
# 1. https://railway.app 접속
# 2. GitHub 연결
# 3. 환경변수 설정
# 4. 배포

# Dockerfile 필요 없음 (자동 감지)
```

**장점:** PostgreSQL/Redis 등 DB 쉽게 추가
**단점:** 무료 크레딧 $5/월

### 7.3 Docker로 자체 서버 배포

```dockerfile
# Dockerfile
FROM node:20-alpine AS builder
WORKDIR /app
COPY package*.json ./
RUN npm ci
COPY . .
RUN npm run build

FROM node:20-alpine AS runner
WORKDIR /app
ENV NODE_ENV=production
COPY --from=builder /app/.next/standalone ./
COPY --from=builder /app/.next/static ./.next/static
COPY --from=builder /app/public ./public

EXPOSE 3000
CMD ["node", "server.js"]
```

```bash
# 빌드 및 실행
docker build -t cheongyak-dashboard .
docker run -p 3000:3000 \
  -e REB_API_KEY=your_key \
  -e NEXT_PUBLIC_KAKAO_API_KEY=your_kakao_key \
  cheongyak-dashboard
```

## 10. 유지보수 고려사항

### 10.1 캐시 업데이트 전략

현재 `npm run dev` 실행 시 `auto-update-cache.js`가 실행됩니다.

**배포 환경에서의 캐시 갱신 방법:**

1. **수동 업데이트**: 로컬에서 캐시 생성 후 Git Push
2. **GitHub Actions**: 정기적으로 캐시 갱신 후 자동 배포
3. **Vercel Cron Jobs**: Pro 플랜에서 사용 가능

#### GitHub Actions 예시 (주 1회 캐시 갱신)

```yaml
# .github/workflows/update-cache.yml
name: Update Cache

on:
  schedule:
    - cron: '0 0 * * 0'  # 매주 일요일 00:00
  workflow_dispatch:

jobs:
  update:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-node@v4
        with:
          node-version: '20'
      - run: npm ci
      - run: npm run generate-cache
        env:
          REB_API_KEY: ${{ secrets.REB_API_KEY }}
      - run: |
          git config user.name "GitHub Actions"
          git config user.email "actions@github.com"
          git add public/data/
          git commit -m "chore: update cache" || exit 0
          git push
```
