## 🚨 문제 현상

### 사용자 보고
조회 기간을 변경했을 때 예상과 다른 결과:

| 조회 기간 | 총 공급 규모 | 총 청약 건수 | 전체 경쟁률 | 1순위 경쟁률 |
|-----------|--------------|--------------|-------------|--------------|
| 2025년 1월 ~ 4월 | 4,341 세대 | 304,011 건 | 70.03:1 | 155.98:1 |
| 2025년 1월 ~ 12월 | 4,009 세대 | 304,011 건 | 75.83:1 | 155.98:1 |

### 이상한 점
1. **총 공급 규모 감소** ⚠️
   - 조회 기간을 늘렸는데 총 공급 규모가 오히려 332세대 감소
   - 논리적으로 불가능 (더 긴 기간 = 더 많은 공급)

2. **총 청약 건수 동일** ⚠️
   - 조회 기간을 3배 늘렸는데 청약 건수가 동일
   - 명백히 잘못된 결과

3. **일부 통계만 변경** ⚠️
   - 전체 경쟁률: 70.03:1 → 75.83:1 (변경됨)
   - 1순위 경쟁률: 155.98:1 (변경 없음)
   - 최고 경쟁률: 688.13:1 (변경 없음)

**문제점:**

1. **날짜 범위 계산 오류**
   ```typescript
   const searchEnd = searchEndYear && searchEndMonth
       ? new Date(searchEndYear, searchEndMonth, 0) // 마지막 날
       : null;
   ```
   - `new Date(2025, 12, 0)` → 2025년 11월 30일 (잘못됨!)
   - 올바른 계산: `new Date(2025, 12 + 1, 0)` → 2025년 12월 31일

2. **캐시 우선순위 문제**
   - 캐시에 있는 데이터는 API 데이터보다 우선
   - 캐시가 오래된 경우, 최신 경쟁률 데이터를 반영하지 못함

3. **중복 제거 로직**
   - 캐시에 있으면 무조건 API 데이터 제외
   - 캐시 범위(2026-01-16)를 벗어난 데이터도 API에서 가져와야 하는데, 중복으로 판단되어 제외될 수 있음

#### 2. 캐시 병합 로직 개선
**파일:** `src/lib/cache-loader.ts:213-247`

```typescript
// ✅ 개선된 로직
export function mergeCacheAndApiData(
    cacheData: CacheData | null,
    apiData: AptInfo[],
    startMonth?: string,
    endMonth?: string
): AptInfo[] {
    if (!cacheData) {
        return apiData;
    }

    // 검색 범위 파싱
    const searchStart = startMonth ? parseDate(startMonth.replace('-', '') + '01') : null;
    const searchEnd = endMonth ? (() => {
        const [year, month] = endMonth.split('-').map(Number);
        const lastDay = new Date(year, month, 0).getDate();
        return new Date(year, month - 1, lastDay, 23, 59, 59);
    })() : null;

    // 캐시 범위 확인
    const cacheEndDateStr = cacheData.metadata?.dateRange?.end || '2025-12-31';
    const cacheEndDate = parseDate(cacheEndDateStr.replace(/-/g, ''));

    // Map으로 중복 관리 (최신 데이터 우선)
    const itemMap = new Map<string, AptInfo>();

    // 1. 캐시 데이터 추가 (날짜 범위 내)
    cacheData.lists.forEach(item => {
        const itemDate = parseDate(item.RCRIT_PBLANC_DE || '');
        if (!itemDate) return;

        // 검색 범위 확인
        if (searchStart && itemDate < searchStart) return;
        if (searchEnd && itemDate > searchEnd) return;

        const key = `${item.HOUSE_MANAGE_NO}_${item.PBLANC_NO}`;
        itemMap.set(key, item);
    });

    console.log(`📦 캐시에서 ${itemMap.size}건 로드`);

    // 2. API 데이터 추가 (중복 시 API 우선 - 최신 데이터)
    let apiAdded = 0;
    apiData.forEach(item => {
        const key = `${item.HOUSE_MANAGE_NO}_${item.PBLANC_NO}`;

        // API 데이터가 캐시 범위를 벗어났거나, 더 최신이면 덮어쓰기
        const itemDate = parseDate(item.RCRIT_PBLANC_DE || '');
        if (itemDate && cacheEndDate && itemDate > cacheEndDate) {
            itemMap.set(key, item);
            apiAdded++;
        } else if (!itemMap.has(key)) {
            itemMap.set(key, item);
            apiAdded++;
        }
    });

    console.log(`🔄 API에서 ${apiAdded}건 추가 (총 ${itemMap.size}건)`);

    return Array.from(itemMap.values());
}
```

**개선 효과:**
- 날짜 범위 정확히 계산
- 캐시 범위를 벗어난 데이터는 API 우선
- 중복 제거 로직 명확화

// 동적 perPage 계산 (조회 기간에 따라)
const getOptimalPerPage = (startMonth: string, endMonth: string): number => {
  const start = new Date(startMonth + '-01');
  const end = new Date(endMonth.split('-')[0] + '-' + endMonth.split('-')[1] + '-01');
  const monthsDiff = (end.getFullYear() - start.getFullYear()) * 12 +
                     (end.getMonth() - start.getMonth());

  // 1개월당 약 50건 예상, 최대 500건
  return Math.min(Math.max(monthsDiff * 50, 200), 500);
};

const perPage = getOptimalPerPage(paramsToUse.startMonth, paramsToUse.endMonth);
