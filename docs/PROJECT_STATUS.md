# 프로젝트 개발 현황 및 인수인계 문서 (PROJECT_STATUS.md)

이 문서는 청약경쟁률 대시보드 프로젝트의 현재 상태와 지금까지 진행된 주요 기술적 의사결정 및 구현 내용을 정리한 것입니다. 다음 작업자가 프로젝트를 즉시 이해하고 이어나갈 수 있도록 구성되었습니다.

---

## 1. 프로젝트 개요
- **목적**: 공용 데이터 API를 활용하여 전국 아파트 청약 정보 및 실제 경쟁률을 지도와 리스트 형태로 시각화.
- **주요 기술 스택**: Next.js, TypeScript, Leaflet (Map), Kakao Maps SDK (Geocoder).

## 2. 데이터 처리 및 캐시 전략 (핵심)
### 2.1. 정적 캐시 (`public/data/cheongyak-archive.json`)
- **이유**: 공공데이터 API의 호출 속도가 느리고, 과거 데이터가 누락되는 경우가 있어 자체 서버/로컬에서 통계치를 계산해 저장함.
- **수집 로직 (`scripts/generate-cache.js`)**: 
    - 2,600여 건의 과거/현재 데이터를 전수 조사.
    - **특별공급 데이터 수정**: `SPSPLY_HSHLDCO`(공급량) 필드와 모든 `_CNT`(접수량) 필드를 합산하여 정확한 경쟁률 산출.
    - **계산 데이터 포함**: `calculatedStats` 필드에 `special`, `rank1`, `rank2`, `total` 경쟁률 및 공급량을 단지별로 미리 계산해 저장.
- **효과**: 클라이언트 로딩 시 수천 건의 상세 API 호출 없이 즉시 경쟁률 표시 가능.

### 2.2. 클라이언트-사이드 병합 (`src/lib/cache-loader.ts`)
- 캐시 데이터와 최신 API 데이터를 ID 기반으로 병합하여 중복 제거 및 최신성 유지.

## 3. 지도 및 시각화 로직 (`src/components/CompetitionRateMap.tsx`)
### 3.1. 줌 레벨별 3단계 집계 (Aggregation)
- **Zoom < 9 (광역)**: 시/도 단위(예: 서울, 경기)로 데이터 통합 표시.
- **Zoom 9 ~ 11 (기초)**: 시/군/구 단위(예: 강남구, 수워니)로 데이터 통합 표시.
- **Zoom 11 이상 (개별)**: 아파트 단지별 개별 마커 표시.
- **좌표 데이터**: `src/lib/geo-coordinates.ts`에 시도/구별 중심 좌표 정의.

### 3.2. 마커 디자인 및 UX
- **알약(Pill) 스타일**: 경쟁률 값을 마커 내부에 `34.20:1` 형태로 직접 표기.
- **색상 코딩**: 경쟁률 수치에 따른 색상 변화 (파랑: 미달 ~ 빨강: 50대1 이상).
- **영구 툴팁**: 줌인 시 아파트 단지명을 마커 상단에 항상 표시.

## 4. 성능 최적화 및 필터링
### 4.1. 초기 로딩 최적화
- **기본 조회 기간**: 데이터 과부하를 막기 위해 초기 접속 시 **최근 1년치** 데이터만 조회하도록 설정. (`src/app/apt/page.tsx` 내부 `oneYearAgo` 계산 로직)
- **지도 크기**: 사용자 시인성 확보를 위해 높이를 **800px** (PC)로 상향 조정.

### 4.2. 검색 및 필터링 강화
- **통합 검색 (Cache + API)**: 검색어 입력 시 API 데이터뿐만 아니라 **로컬 캐시 데이터(2,600건)**를 실시간으로 병합하여 리스트에 표시. (기존에는 API 최신 데이터만 리스트에 보였던 문제 해결)
- **지역 코드 보정**: UI 코드(2자리, 예: 41)와 API/캐시 코드(3자리, 예: 410) 간의 불일치를 해결하여 '경기도' 등 지역 검색이 누락 없이 작동하도록 보정.
- **공공분양/임대 제외**: 경쟁률 데이터가 없거나 형식이 달라 사용자 혼동을 주는 '공공분양', '임대', '신혼희망타운' 등을 주택명(`HOUSE_NM`) 및 유형(`HOUSE_DTL_SECD_NM`) 체크를 통해 엄격하게 제외.

## 5. 알려진 설정 및 주의사항
- **API 키**: `.env.local`의 `NEXT_PUBLIC_KAKAO_API_KEY` 필수.
- **지오코딩**: REST API 대신 클라이언트 사이드 Kakao SDK Geocoder를 사용 (`window.kakao.maps.services.Geocoder`). 이는 도메인 인증 및 쿼터 관리를 위함임.
- **진행 중인 작업**: 주기적인 캐시 업데이트(`node scripts/generate-cache.js`) 필요.
